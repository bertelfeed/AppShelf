# Уведомления об Issues в Telegram

Когда кто-то открывает Issue в `bertelfeed/AppShelf` или открывает закрытый заново,
GitHub Actions присылает короткое сообщение в один чат Telegram: репозиторий, номер
и название, метки, автор и ссылка. Текст Issue в сообщение не попадает: в нём бывают
личные данные, а чат нужен только как указатель на GitHub.

Что работает:

- workflow [`.github/workflows/issues-telegram.yml`](../.github/workflows/issues-telegram.yml);
- скрипт [`.github/scripts/issue_to_telegram.py`](../.github/scripts/issue_to_telegram.py), только стандартная библиотека Python.

Пока секреты не заданы, workflow завершается успешно, пишет в журнал notice и ничего
не отправляет.

## 1. Создать бота

1. В Telegram откройте [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Введите имя бота, например `AppShelf Feedback`.
3. Введите username, он должен заканчиваться на `bot`, например `appshelf_feedback_bot`.
4. BotFather пришлёт токен вида `123456789:AAH...`. Это пароль от бота: не публикуйте
   его и не коммитьте. Если токен утёк, в BotFather выберите бота и выпустите новый
   (`/revoke`), затем обновите секрет из шага 3.

## 2. Узнать id чата

Бот не может первым написать человеку или попасть в группу сам, поэтому сначала
нужно сообщение от вас.

### Личный чат с ботом

1. Найдите бота по username и нажмите **Start** (или отправьте `/start`).
2. Откройте в браузере, подставив свой токен:
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
3. В ответе найдите `"chat":{"id":123456789,...`. Это число и есть id чата.
   У личного чата оно положительное.

### Группа

1. Создайте группу (или откройте существующую) и добавьте в неё бота как участника.
2. Отправьте в группе команду с именем бота, например `/start@appshelf_feedback_bot`.
   По умолчанию бот в группе видит только команды и обращения к нему, обычное
   сообщение в `getUpdates` может не появиться.
3. Откройте тот же адрес `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите
   `"chat":{"id":-1001234567890,"title":"...","type":"supergroup"}`. У группы id
   отрицательный, у супергруппы начинается с `-100`. Копируйте его целиком, с минусом.

Если `getUpdates` вернул пустой `"result":[]`, отправьте сообщение ещё раз и обновите
страницу: Telegram хранит эти обновления сутки. Адрес с токеном останется в истории
браузера; если это общий компьютер, очистите её.

Если обычную группу потом превратят в супергруппу (это случается само, например при
включении истории для новых участников), id изменится. Отправка упадёт с ошибкой
`group chat was upgraded to a supergroup chat`; новый id есть в ответе Telegram
(`migrate_to_chat_id`) и в `getUpdates`.

## 3. Добавить секреты в репозиторий

1. На GitHub откройте репозиторий → **Settings** → **Secrets and variables** → **Actions**.
2. На вкладке **Secrets** нажмите **New repository secret** и создайте два секрета:

   | Name | Secret |
   | --- | --- |
   | `TELEGRAM_BOT_TOKEN` | токен из шага 1 |
   | `TELEGRAM_CHAT_ID` | id чата из шага 2, например `123456789` или `-1001234567890` |

Значения секретов после сохранения не видны никому, в журналах Actions GitHub их
маскирует, а скрипт токен не печатает. Секреты не передаются в запуски из форков,
и этот workflow на pull request не запускается вообще.

## 4. Проверить вручную

Workflow должен быть в ветке по умолчанию (`main`), иначе GitHub не покажет кнопку
запуска и не будет реагировать на Issues.

1. Откройте **Actions** → слева **Issues to Telegram**.
2. Нажмите **Run workflow**, оставьте ветку `main` и снова **Run workflow**.
3. Через несколько секунд в чат придёт сообщение с пометкой **🧪 ТЕСТ** и ссылкой на запуск.

После этого можно открыть пробный Issue: придёт сообщение «🆕 Новый Issue».
Пробный Issue потом закройте.

## Где смотреть ошибки

**Actions** → **Issues to Telegram** → нужный запуск → задача `notify` → шаг
**Send to Telegram**. Неудачная отправка помечает запуск красным.

| Что в журнале | Что значит |
| --- | --- |
| `TELEGRAM_BOT_TOKEN or TELEGRAM_CHAT_ID is not set` (запуск зелёный) | Нет одного из секретов или имя написано с ошибкой. |
| `Telegram HTTP 401: Unauthorized` | Неверный или отозванный токен. |
| `Telegram HTTP 400: Bad Request: chat not found` | Неверный id чата, бот не в группе или вы не нажали Start в личном чате. |
| `Telegram HTTP 403: Forbidden: bot was blocked by the user` / `bot was kicked` | Бота заблокировали или удалили из группы. |
| `Telegram HTTP 400: ... upgraded to a supergroup chat` | Группа стала супергруппой, нужен новый id (см. шаг 2). |
| `Telegram HTTP 429` или `5xx`, затем `Retrying in N s.` | Telegram попросил подождать; скрипт повторяет отправку один раз. |

Формат сообщения можно проверить у себя, ничего не отправляя:

```bash
python .github/scripts/issue_to_telegram.py --self-test
```

## Сколько стоит

В публичном репозитории запуски на стандартных раннерах GitHub (`ubuntu-latest`)
бесплатны. В приватном они расходуют бесплатные минуты Actions из месячной квоты
аккаунта; один запуск длится несколько секунд, но округляется до минуты. Бот Telegram
бесплатный. Серверов и платных сервисов нет.

## Ограничения

- События Actions иногда приходят с задержкой в несколько минут, при сбоях GitHub дольше.
- Уведомления только об открытии и повторном открытии Issue. Комментарии, закрытие,
  pull request и GitHub Discussions не отслеживаются.
- Запуски идут по одному. Пока идёт один, GitHub держит в очереди ещё один, а более
  ранний ожидающий отменяет. Если за несколько секунд откроют три Issue и больше,
  часть уведомлений пропадёт. Сами Issues на GitHub сохраняются, их полный список
  во вкладке **Issues**.
- Длинные названия обрезаются до 200 символов, метки показываются первые десять.
